## Honest blockers that code cannot erase

- **No demonstrated edge (high, scientific):** 13 trades are not statistically meaningful, and the plain headline baseline wins on the same main-mode releases. Tuning the backtest after seeing this would make the evidence weaker, not stronger.
- **Two execution universes (high, product constraint):** Bitget Demo does not list the ETF hedges used by main mode. Demo-executable mode is a separately scored restriction, not an execution-time substitute for a main-mode hedge. The UI and logs must keep that distinction explicit.
- **Limited funding history (medium):** Bitget exposes only a short historical window. Older results therefore use the disclosed worst-case charge; they cannot be reconstructed as observed funding without another contemporaneous source.
- **Small, liquidity-bound sample (medium):** after-hours depth legitimately rejects many events. Lowering the gate simply to create more trades would undermine the risk thesis.
- **LLM run variance (low):** live labels can vary, while replay is reproducible because validated responses are cached by prompt hash. The LLM remains sizing-only and cannot invent trade numbers.

## Verification contract

The branch must pass unit/regression tests, offline SEC provenance verification, an offline replay whose main and Demo-mode decisions match committed artefacts, strict JSON parsing, and a clean diff check. No private credentials or real-money endpoints are needed for those checks.
